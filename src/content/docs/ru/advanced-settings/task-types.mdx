“Интабия Платформа” может быть настроена под любой тип рабочего процесса. Она постоянно дорабатывается с учётом нужд пользователей. Хотя некоторые функции настройки всё ещё разрабатываются, уже доступно несколько опций для настройки вашего рабочего пространства под ваши конкретные нужды.

## Что такое типы задач?

Типы задач определяют виды задач внутри ваших проектов. Тип задачи может иметь свои собственные специальные свойства и состояния процесса.

Чтобы посмотреть на тип задачи по умолчанию, используемый в вашем Трекере, необходимо:
* нажать на значок “Аккаунта” внизу главного бокового меню;
* в появившемся окне выбирать раздел “Настройки”;
* перейти в раздел `ТИПЫ ПРОСТРАНСТВ`->`Классический проект`. `Классический проект` — это [тип пространства](/ru/advanced-settings/space-types) по умолчанию, используемый в "Интабия. Платформа".

В разделе `ТИПЫ ЗАДАЧ` указан один тип задач: `Classic Issue`. Открытие этого типа задачи покажет его свойства и состояния процесса.

Тип задачи `Classic Issue` имеет состояния процесса `Backlog`, `Todo`, `In Progress`, `Done` и `Canceled` — названия состояний не переводятся и показываются на английском независимо от языка интерфейса.

## Состояния процесса

Состояния процесса — это этапы, через которые задача проходит в своём жизненном цикле. Каждый тип задачи может иметь свой собственный набор состояний процесса, сгруппированных по `Категории статуса` (`Пул задач`, `Не запущенные`, `Активные`, `Завершено / Выиграно`, `Завершено / Потеряно`).

Если задаче назначен исполнитель и её статус относится к категории `Не запущенные` или `Активные` (в типе задачи `Classic Issue` это статусы `Todo` и `In Progress`), система автоматически создаёт для исполнителя [действие](/ru/task-tracking/creating-action-items) в его Планировщике. Завершение или перепланирование этого действия статус самой задачи больше не меняет — эти два события не связаны друг с другом.

Даже если вы настроите свои состояния процесса с использованием других названий (см. ниже), система всё равно распознает это правило на основе `Категории статуса` состояния процесса. Например, вы можете изменить название состояния процесса с «В работе» на «Активно работаю», и пока `Категория статуса` установлена как «Активные», система всё равно будет создавать действие при назначении исполнителя на задачу в этом состоянии.

## Создание пользовательских типов задач

Чтобы использовать свои собственные настроенные типы задач и состояния процесса, вы можете либо изменить типы задач по умолчанию в `Классический проект`, либо создать новый [тип пространства](/ru/advanced-settings/space-types). Это может сделать только владелец или администратор рабочего пространства.

Чтобы создать новый тип пространства, необходимо:
* нажать на значок “Аккаунта” внизу главного бокового меню;
* в появившемся окне выбирать раздел “Настройки”;
* перейти в раздел `ТИПЫ ПРОСТРАНСТВ`->нажмите кнопку `+`;
* выберите тип пространства, на котором вы будете основывать новый тип пространства; в данном случае вы выберете `Трекер`. Здесь вы можете ввести название для вашего типа пространства (например, «Пользовательский трекер») и выбрать, хотите ли вы основать тип пространства на `Классический проект` (рекомендуется);
* затем нажмите `Создать`.

Найдите ваш новый тип пространства в левом боковом меню. Здесь вы можете добавить участников к типу пространства и переключить, будут ли новые участники рабочего пространства автоматически добавляться к этому типу пространства.

Нажмите кнопку `+` в разделе `ТИПЫ ЗАДАЧ`. Введите название для вашего нового типа задачи (например, «Задача» или «Тикет»), выберите, может ли этот тип использоваться для подзадач, и нажмите `Создать`.

Шаги для создания и изменения типов задач в `Классический проект` такие же.

## Создание пользовательских состояний процесса

Откройте ваши новые типы задач, чтобы создать пользовательские состояния процесса. Вы увидите параметры для каждой категории, каждый из которых может быть отредактирован под ваши конкретные нужды.

Нажмите на любое состояние процесса, чтобы отредактировать его. Вы можете изменить название состояния и связанный с ним цвет. Категорию статуса можно выбрать только при создании нового состояния — у существующего она недоступна для изменения; именно эта категория используется для создания Действия в Планировщике исполнителя (см. выше).

Вы также можете создавать новые состояния процесса. Например, в категории статуса «Активные» вы можете добавить больше состояний, таких как «Начато», «В работе», «Отправлено на проверку» и «На проверке». Вы также можете добавить более конкретные состояния, такие как «Отменено», «Приостановлено» или «Заблокировано».

## Использование пользовательских типов задач

Чтобы использовать ваши пользовательские типы задач, вам нужно создать новый проект на основе вашего нового типа пространства. В настоящее время невозможно изменить тип пространства, используемый для существующего проекта.

При создании нового проекта выберите ваши пользовательские типы задач из выпадающего меню `Тип проекта`.

<Shot src={newCustomProject} alt="Использование пользовательского типа проекта" />

Теперь при создании новых задач в вашем проекте вы найдёте все ваши пользовательские типы задач и состояния процесса, доступные для использования.
